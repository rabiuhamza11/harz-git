## THE FINISH LINE (Dad's shape, frozen verbatim in intent)

HARZ AI → ONE FRONT DOOR → ONE TASK CONTRACT → ONE
ORCHESTRATOR → CAPABILITIES UNDERNEATH → VERIFICATION →
RECEIPT → USER-VISIBLE RESULT.

## THE FINAL GATE (brutal, no exceptions)

Create → Test → Verify → Browser/live test → Receipt.

No component is "done" because its endpoint responds. A
component is done only when it works inside the composition,
verified live, receipted.

## THE NO-PRETENDING LAW

"Give it a task." That is the acceptance test. A real person
hands HARZ AI an arbitrary real-world task through the front
door and receives a verified, receipted, user-visible result —
or an honest refusal with the reason. Anything less is not
finished.

   user" — the actual file must reach Dad.
